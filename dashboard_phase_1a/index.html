12. Quiet Strategies (producer-zero audit)

  
Strategies with 0 fires in cube. Per producer_zero_post_cube_audit.json: 3-bucket classification by gate-key empirical emission.


  
  

    What do these buckets mean? (click to collapse)
    

      
The setup. A strategy is a list of entry conditions joined by AND (e.g. near_52w_high AND price_above_ema_200 AND resistance_break_retest). Each condition has a "producer" - the function that computes whether the condition is true today on this ticker. If a strategy fires zero trades in a backtest, it's "quiet". The optimizer (producer_zero_post_cube_audit.json) classifies the reason into one of three buckets so you know whether to fix the producer, restructure the rules, or loosen a downstream gate.


      
1. PRODUCER_LAYER_ZERO_LIKELY (broken signal feed).

      
At least one of the strategy's clauses NEVER returns truthy on any day or ticker in the backtest window. The producer is silently broken: bad data path, schema drift, exception caught and discarded. The strategy can't fire because its required ingredient is missing.

      
Example. SMC clauses depend on compute_smc_signals in backtest/signals/smc_ict.py. If the vendored library fails to import in the AWS environment, every SMC clause returns false silently. Batch 416 wired diagnostic logging so the actual failure mode shows up in backtest.signals.screener logs at the next cube re-run.

      
Fix: repair the producer (data path, schema, import) - not the strategy rules.


      
2. COMPOUND_RESTRICTIVE (clauses fire alone but AND never satisfies).

      
Each individual clause emits truthy on a reasonable share of days/tickers, but when you AND them all together the joint condition almost never happens. Everyday analogy. "I want to go for a run if it's sunny AND between 60-70F AND weekend AND my running partner is free AND I had at least 7 hours sleep." Each individual condition is common; the AND of all 5 might happen twice a year.

      
Trading example. A strategy with clauses near_52w_high (fires 8% of ticker-days), price_above_ema_200 (60%), resistance_break_retest (5%). Each clause is fine on its own. But the AND - multiplied with correlation discount - lands around 0.1% of ticker-days, then liquidity/sector/regime gates trim further until zero trades.

      
Fix: open Tab 11 -> pick the strategy -> dimension_b_compound section shows per-clause fires_at rates. The restrictive array is the AND-killer (low fire rate). The always_on array fires ~100% of the time - those don't add any restriction, drop them. The proposals array is the optimizer's suggestion.


      
3. SKIPPED_AT_ENGINE (downstream gate kicks the trade).

      
The strategy DOES generate candidate trades that pass the screener, but a downstream engine gate rejects them: liquidity floor (ADV too low), position-size cap full, daily-cash limit, ticker-uniqueness (already in a position on this ticker), confidence tier too low.

      
Example. A small-cap momentum strategy generates 30 candidates a day on illiquid tickers. ADV floor rejects all 30. Strategy looks quiet from the outside.

      
Fix: Tab 8 (Skipped) shows reason codes per skipped trade. Either loosen the gate (e.g. tier the strategy to a smaller-cap universe with a lower ADV floor) or accept the strategy is incompatible with current rules.


      
Quick decision rule: PRODUCER fix the data; COMPOUND restructure the rules; SKIPPED loosen the downstream gate or move the strategy to a more permissive tier.

        Position sizing (confidence tiers)
        
  
        Two-stage process (Batch 438 correction - prior table tied sizing to the 9 criteria, which was wrong). Stage 1 assigns a preliminary tier per-trade at entry from rule-based confluence. Stage 2 lets agent scores shift the tier +/-1 in Phase 1B+. Phase 1A-beta has no agents, so Stage 2 is a no-op and Stage 1 is final. The strategy-level 9-criteria verdict (Tab 1's PASS pill) is a POST-HOC backtest summary; it does NOT feed into per-trade sizing.

        strategy_count >= 3MEDIUM_HIGH
        
      
        strategy_count >= 2MEDIUM
        
      
        strategy_count >= 1 AND sm.score >= 2LOW

        Stage 2 - Agent tier adjustment (Phase 1B+ only)
        
  
        Source: backtest/engine/backtest.py::_adjust_tier_by_agent. In Phase 1B-alpha the agent pipeline (11 active LLM nodes per propagate()) returns a 0-100 score per trade. Score >= 75 upgrades the preliminary tier by one slot; score <= 40 downgrades by one. Phase 1A-beta has agents OFF, so Stage 2 is a no-op and the preliminary tier IS the final tier.
        

  
        Concrete example - Phase 1A-beta (no agents)
        
  
        
    
        Setup. Starting equity = $100,000. Date = 2026-05-20. Ticker = AAPL @ $185.
        
    
        Example A - EXCEPTIONAL. On this day, 4 strategies fire on AAPL: near_52w_high, rsi_oversold_reversion, bollinger_tight, ma_crossover. Smart money signal: congressional buys + insider cluster buys = congressional+insider_cluster. Rule match: "smart-money = congressional+insider_cluster AND strategy_count >= 4" -> preliminary tier = EXCEPTIONAL. No agents in 1A-beta -> final tier = EXCEPTIONAL. Position = $100,000 x 5.0% = $5,000 = 27 shares.
        
    
        Example B - MEDIUM. Same day, MSFT. 2 strategies fire. No smart-money signal. Rule match: "strategy_count >= 2" -> MEDIUM -> $100,000 x 0.75% = $750.
        
    
        Example C - SKIP. NVDA. 1 strategy fires. Smart-money score = 0. Final rule "else" -> LOW -> no trade.
        
    
        Example D - AVOID. META. 5 strategies fire. But smart money signal: congressional sell + insider cluster sell. The first rule kicks in: -> AVOID regardless of confluence -> no trade.
        
  
        

  
        Why "9 criteria" is mentioned elsewhere but NOT here
        
  
        Tab 1 (Strategies) shows a PASS pill if a strategy's POST-HOC backtest aggregate passed the 9 criteria (win rate / PF / EV / W:L / DD / ROI / smart-money lift / macro / min trades). That is a strategy-level summary computed AFTER the backtest finished, used for strategy approval/deprecation decisions. It does NOT influence per-trade sizing - the strategy could have an overall FAIL pill yet still emit individual trades during the backtest, and each of those trades got a tier from Stage 1 above. Sharpe (criterion 10) and per-regime verdict (criterion 11) are evaluated separately, which is why the dashboard sometimes says "9" and sometimes "11" - 9 are the legacy passes_all gates, +2 are tracked separately.

    Trade 1 - EXCEPTIONAL win (cluster + confluence + follow-through)

Screener fires 4 strategies on AAPL: near_52w_high, rsi_pullback, breakout_retest, ma_crossover_bullish -> strategy_count = 4. Smart-money producers run: congressional disclosure 14 days old shows 3 senators bought AAPL; insider feed shows 2 Form 4 buys this week -> composite_signal = congressional+insider_cluster.
        
    
        Stage 1 _assign_confidence_tier: first rule match = "smart-money = congressional+insider_cluster AND strategy_count >= 4" -> EXCEPTIONAL.
        Stage 2 _adjust_tier_by_agent: Phase 1A-beta has agents off -> no-op -> final tier = EXCEPTIONAL.
        
    
        Sizing: $100,000 x 5.0% = $5,000 -> floor($5,000 / $185) = 27 shares ($4,995 deployed). Initial stop $173.90 (6% below). Exit method: atr_trail_1x.
        Days 1-18: price drifts up to $208 on day 12 (high-water); trailing stop ratchets to $202. Day 18 close $202 -> trailing stop hits. Exit @ $202.00. PnL = 27 x $17 = +$459.
        
  
        
  
        
    Trade 2 - MEDIUM_HIGH win (3 strats, no smart money)

Stage 1 first matching rule: "strategy_count >= 3" -> MEDIUM_HIGH (1.5%). $100,459 x 1.5% = $1,506.89 -> 3 shares x $410 = $1,230 (capital efficiency drops on high-priced tickers). 12 days. Exit @ $425. PnL = 3 x $15 = +$45.

Stage 1 first rule: composite_signal == "congressional_sell+insider_cluster_sell" -> AVOID regardless of confluence -> no trade. This catches insider-cluster-coordinated distribution before a drop.

        Takeaway. This sample is engineered to land near break-even on purpose - it mirrors the empirical cube finding (most cells fail strict 5-Gate). A 62.5% win rate sounds good, but with 0.63 W:L ratio + only 8 trades, profit factor 1.04 doesn't clear the 1.5 overall threshold. To pass the 9 criteria the strategy mix needs EITHER higher win rate (~70%) OR larger avg-win/avg-loss ratio (~1.5+). The cube optimizer (Tab 11) is what hunts for parameter combinations that achieve this.
