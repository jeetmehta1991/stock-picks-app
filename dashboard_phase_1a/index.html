        What this dashboard is. A read-only post-mortem of one backtest run plus the cube optimizer outputs that derive from it. Nothing here runs live trading.

        The same inclusion threshold applies in both runs - "fired >= 1 trade" - but the cube's relaxed gates let 64 more strategies actually place a trade. Those 64 weren't pruned; the baseline gates simply blocked their candidates before they hit the trade log. The 85 quiet count is cube-only (strategies that didn't fire even with all gates off).
        

    
        Recommended reading order: Overview (portfolio health) -> Tab 1 (strategy ranking, see inclusion criteria there) -> Tab 2 (per-regime) -> Tab 4 (equity curve) -> Tab 13 (cube cell verdicts) -> Tab 10 (cube optimizer's recommendations) -> Tab 11 (drill down on a strategy) -> Tab 12 (zero-fire diagnosis).
        
    
        What "good" looks like. Portfolio Sharpe >= 0.7 OOS in >= 1 regime (the 1A-alpha gate). Per-strategy: passes the 9-criteria gates (see table below) AND has a cube cell that passes the DEC-426 5-Gate (also below). Currently the 1A-alpha gate is LOCKED at OOS Sharpe 0.419 - a cube re-run is in flight.

        DEC-426 5-Gate (Phase 1A-β cube cell-level — different from the 9 criteria above)
        
  
        Per-(strategy × exit × regime) cell-level gate used by the cube optimizer. Stricter than the 9 criteria because each cell has fewer trades — the gates correct for multiple-testing.
        
  
        
    
        GateThresholdPurpose
        
    
      
        n≥ 30Minimum trades for statistical power
        
      
        p (Bonferroni)< 0.05Multiple-testing correction across 4625 cells/regime
        
      
        PSR (Probabilistic Sharpe)≥ 0.95Prob. that true Sharpe > 0; strict 5-Gate gate
        
      
        t-stat≥ 3.4Bailey-Lopez de Prado strict significance
        
      
        R:R≥ 2.0Edge over implementation costs

        Glossary
        
  
          
    
        • PIT (point-in-time) — data filtered to what would have been known at decision time; no lookahead.
          • 
    
        • Cube — Phase 1A-β cube = 185 strategies × 25 exits × 7 regime windows = ~32,375 cells per regime window evaluated.
          • 
    
        • 1A-α gate — owner gate: ≥1 strategy with rules-only Sharpe ≥ 0.7 OOS in ≥1 regime. Currently LOCKED at 0.419 (best). Gate must open before Phase 1B-α $300 agent budget.
          • 
    
        • 1A-β cube re-run — full re-evaluation of cube on AWS spot infrastructure. Currently running Shape A: 3 × c7a.8xlarge spot, ~$9.30, ~5h.
          • 
    
        • 5-Gate (DEC-426) — strict cell-level gate above. Differs from the 9 criteria which are strategy-level overall.
          • 
    
        • Smart money — aggregated congressional trades + insider buys + 13F flows. Acts as a quality multiplier on candidate trades.
          • 
    
        • BUG-95 portfolio metrics — per-trade aggregates differ from compounded portfolio returns once position sizing + heat caps apply. The dashboard exposes both views.
          •

          3.

          4. 
    
        4. Metrics — results/metrics.py computes the 9 criteria + per-regime verdict from trade outputs.
          5. 
    
        5. Dashboard build — scripts/build_dashboard_phase_1a.py serializes all outputs into data.js for this dashboard.
          6. 
    
        6. Cube optimizer — scripts/optimize_strategies_from_cube.py emits the Stage 3 candidates (Tab 10/11) + verdict cube (Tab 13).
          7. 
    
        7. Walk-forward — scripts/walk_forward_batch414_cells.py implements DEC-505 4-fold expanding-window for the 1A-α gate.
